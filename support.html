01

Crashes and startup problems

For DNS Browser closing unexpectedly, failing to launch, or showing runtime errors.

DNS Browser closes or crashes when I open itStartup crash · Runtime dependency · Windows

Try these checks in order:

  1. Restart Windows and open DNS Browser again. Close other copies of the app first.
  2. Make sure the app was installed or extracted completely. If files are missing, download a fresh copy from the Miveyo Download Center and reinstall it. Back up any browser data you need before reinstalling.
  3. If Windows reports a missing C++ runtime or a CefSharp dependency, install the Microsoft Visual C++ Redistributable that matches the app's architecture. For an x64 build, use the official Microsoft x64 redistributable. Follow the app's release requirements if they specify a different runtime.
  4. Check Windows Security or your antivirus quarantine for files removed from the official app package. Restore or allow files only when you can verify they came from the genuine Miveyo download.

Do not download individual DLL files from third-party DLL websites, and do not disable your antivirus to make the browser start.

Missing CefSharp files or “Could not load file or assembly”CefSharp.Core.dll · BrowserSubprocess · libcef.dll

CefSharp relies on native libraries, resource files, and its browser subprocess. An incomplete copy or installer can prevent the browser engine from starting.

  1. Reinstall or extract the complete DNS Browser package. Do not copy only the main executable to another folder.
  2. Keep the application files and their resource folders together. Do not rename or manually replace CefSharp files.
  3. Confirm that the downloaded build matches your Windows/app architecture (x64 or x86).
  4. If the error remains, note the exact missing filename and DNS Browser version when reporting the issue.

CefSharp's documentation lists the Visual C++ runtime and the full set of deployed native/resource files as common causes of this error.

Read the CefSharp deployment FAQ ↗
The browser crashes while browsing or watching videoRenderer crash · GPU process · Debug log
  1. Update your graphics driver from Windows Update or your PC/GPU manufacturer's official support page.
  2. Close unused tabs and other demanding apps, then test the same page again.
  3. If DNS Browser provides a hardware-acceleration option, switch it off temporarily and restart the browser to compare. If there is no such setting, do not edit hidden configuration files or add command-line flags yourself.
  4. Check whether the crash happens on one website or on every website. A single-site crash may be related to that page's video, graphics, or scripts.

If the app exits completely, open Event Viewer → Windows Logs → Application and look for an error at the time of the crash. Record the faulting application/module and exception code. A Debug.log file may also be present in the app folder, depending on the build.

02

Blank pages, display and performance

For white or black screens, flickering, rendering problems, and slow pages.

A website opens as a blank, white, or black pageBlank screen · Rendering · Graphics driver
  1. Reload the page, then open a different website. If only one site is affected, the problem may be specific to that website.
  2. Close and reopen DNS Browser. Check whether the page still appears blank in a new tab.
  3. Update your graphics driver and restart Windows.
  4. If a hardware-acceleration setting is available in DNS Browser, test with it disabled. Change one setting at a time so you can tell which change helped.
  5. If the page still fails, note the website address (remove private query parameters if necessary), the browser version, and whether the issue occurs on other devices.

CefSharp's troubleshooting guide recommends checking graphics-driver issues and testing GPU acceleration when diagnosing rendering problems. The exact setting is controlled by each app.

DNS Browser feels slow, freezes, or uses a lot of memoryPerformance · High memory · Unresponsive tabs
  1. Close tabs you are not using, especially pages with video, large web apps, or many animated elements.
  2. Close and reopen the browser to release resources held by old tabs.
  3. Check Windows Task Manager to see whether CPU, memory, disk, or network usage is already high before blaming the browser.
  4. Update DNS Browser and your graphics driver when updates are available.
  5. If one website causes the slowdown, test it separately and report the page and steps that reproduce the issue.

Avoid deleting the entire browser profile as a first step. It can remove saved sessions, settings, and other local data.

03

Network and DNS problems

For pages that cannot connect, DNS lookup failures, timeouts, and certificate warnings.

DNS Browser says there is no internet connectionOffline · Network disconnected · VPN or proxy
  1. Open the same website in another browser or app. If nothing connects, troubleshoot the Windows network or router first.
  2. Check Wi-Fi or Ethernet connectivity and restart your router only if other devices are also affected.
  3. If you use a VPN or proxy, check whether it is connected and configured correctly. Temporarily test without it only when you are allowed to do so on that network.
  4. Check Windows Settings → Network & internet → Proxy for an unexpected proxy configuration. Do not change work, school, or managed-network settings without the administrator's instructions.
  5. Make sure DNS Browser is not being blocked by a firewall rule. Do not turn the firewall off; only review or allow the genuine app when you trust its source.
“ERR_NAME_NOT_RESOLVED” or a DNS lookup error appearsDNS failure · Domain not found · Custom DNS
  1. Check that the website address is spelled correctly and try opening another site.
  2. If DNS Browser has a custom DNS or per-site DNS setting enabled, temporarily return the affected site to Auto/Default and test again.
  3. Open Command Prompt in Windows and run ipconfig /flushdns to clear the Windows DNS resolver cache. Then restart DNS Browser and retry.
  4. If the same domain fails on other devices and networks, the domain or its DNS provider may be having an outage.

Changing DNS providers can affect privacy, filtering, and parental-control policies. Use a provider you trust and change only the setting needed for the test.

“ERR_CONNECTION_TIMED_OUT” or “ERR_CONNECTION_RESET”Connection timeout · Connection reset · Site unreachable
  1. Retry after a minute and test another website. The destination server may be unavailable or overloaded.
  2. Check whether the same site loads on another device using the same network.
  3. Review VPN, proxy, DNS, and firewall settings if the error affects many websites. Change one setting at a time and restore the original value if it does not help.
  4. If the issue occurs only on one network, test a different trusted connection to help identify whether the router or network policy is involved.
“Your connection is not private” or an SSL/certificate errorHTTPS · Certificate date · Secure connection
  1. Check that Windows date, time, and time zone are correct, then sync the system clock.
  2. Update Windows and DNS Browser, then retry the page.
  3. If you use a VPN, proxy, or security product that inspects HTTPS traffic, check its configuration or consult its administrator.
  4. Do not bypass certificate warnings or install certificates from unknown websites. If the warning appears only on one site, the site's certificate may be misconfigured.
04

Updates, cache and browser data

For keeping the browser current and managing locally stored information.

A website keeps showing old content or behaves incorrectlyCache · Cookies · Site data
  1. Reload the page and check whether the issue occurs in another tab.
  2. Use DNS Browser's browsing-data controls to clear cached images and files for a test.
  3. Clear cookies or site data only when necessary. This may sign you out of websites and remove site preferences.

Do not manually delete random folders from the browser's profile or cache directory. Back up important local browser data before performing a reset.

How do I check for DNS Browser updates?Update · New version · Release notes

Open DNS Browser settings and look for the update option. If the installed release provides Check for updates, select it and follow the on-screen instructions.

You can also check the Download Center and Release Notes for published versions and changes. DNS Browser 3.0 availability may differ while it is in development.

How do I transfer browser data to another computer?Data transfer · Backup · Migration

Use the DNS Browser data-transfer guide for the available transfer instructions. The exact data that can be moved depends on the browser version.

Before moving or replacing browser data, close DNS Browser and keep a separate backup of the original files. Never upload browser profile folders publicly; they may contain cookies or other private information.

05

Older DNS Browser versions

Historical guidance for releases that are no longer the current development target.

Archived requirements and crash guidance for older releasesDNS Browser 1.0 · 1.5 · 2.0 Beta

The original support page listed these minimum requirements for older DNS Browser 2.0 builds:

  • Operating system: Windows Vista, Windows 7, Windows 8.x, or Windows 10. The original 2.0 notes also mentioned Windows 11.
  • RAM: 1 GB.
  • CPU: 1 GHz dual-core processor.
  • GPU: A dedicated graphics card was not listed as a requirement.

For DNS Browser 1.0, 1.5, and 2.0 Beta, the original guidance suggested installing .NET Framework 4.6.1 if it was missing, then restarting Windows.

These are archived historical requirements, not verified requirements or compatibility guarantees for DNS Browser 3.0. Older operating systems and releases may no longer receive support.

Help us identify the problem

When reporting an issue, include the DNS Browser version, Windows version, the exact error message, what you were doing, and the steps that reproduce the problem. For a crash, include the approximate time and any relevant Event Viewer details.

Remove passwords, authentication tokens, private browsing data, and personal information before sharing logs or screenshots.
